# results/ — what each file represents

Generated by `../analysis/run_analysis.py`. **Do not edit by hand** — re-run the
pipeline to regenerate. Every GeoJSON is **EPSG:4326 (lon/lat, CRS84)**; all areas are
computed in EPSG:3414 (SVY21) and expressed in **hectares (ha)**.

There are three geometry layers plus two JSON reports. The three layers are the inputs
and output of one spatial operation:

```
forest_all.geojson  (OSM forest)                    ┐
                                                     ├─►  threatened_forests.geojson
development_zones.geojson  (URA MP2025 dev polygons) ┘     (the overlap = OSM ∩ URA)
```

`forest_all` and `development_zones` are the two **source** layers; `threatened_forests`
is their **intersection** — the planned-deforestation footprint. Keeping all three lets
the app show *why* a patch is flagged, not just the result.

---

## 1. `threatened_forests.geojson` — the headline result
**Source:** `OSM_forest ∩ URA_MP2025` · **Geometry:** Polygon/MultiPolygon · **624 features**

Standing OSM forest that MP2025 zones for development. **One feature per OSM forest
polygon**; its geometry is only the part that falls on development-zoned land (the
overlap). Sorted by `area_ha` descending.

| Property | Meaning |
| --- | --- |
| `id` | OSM object id of the source forest polygon |
| `rank` | 1 = largest threatened area |
| `label` | Display name: OSM `name` if present; else `"<Site> (forest patch)"` if the patch falls inside a known AOI (e.g. Gillman Barracks); else `"Unnamed forest near <locality>"` |
| `name` | OSM forest name, or `null` |
| `locality` | Nearest OSM locality (e.g. "Simpang", "Tagore") — used when unnamed |
| `area_ha` | **Threatened area** (forest ∩ development zones), hectares |
| `forest_area_ha` | Total area of the whole forest polygon (Singapore-clipped) |
| `threatened_fraction` | `area_ha / forest_area_ha` (0–1); ~1 means the whole patch is zoned for development |
| `dominant_lu_desc` | The MP2025 land-use class taking the most area of this patch |
| `lu_desc_breakdown` | JSON string: `{LU_DESC: ha}` across all zones overlapping this patch |
| `gpr` | Plot ratio(s) of the overlapping zones — numeric gross plot ratio, or a URA code (e.g. `LND`, `EVA`) where no ratio is assigned |
| `centroid_lon`, `centroid_lat` | A representative point inside the patch (for map labels/markers) |
| `source_layer` | OSM layer the forest came from (`natural`; `landuse` is empty in this extract) |
| `context`, `wildlife`, `status` | Curated background from `analysis/site_context.py` — matched by OSM `name`, or by AOI bbox for unnamed announced sites like Gillman Barracks; else `null` |
| `source` | `"OSM_forest ∩ URA_MP2025"` |

## 2. `forest_all.geojson` — context: all mapped `natural=forest` in Singapore
**Source:** `OSM` · **Geometry:** Polygon/MultiPolygon · **831 features**

Every OSM **`natural=forest`** polygon **inside Singapore**, whether threatened or not.
Use as a base layer so the map shows total forest with the threatened parts highlighted
on top. The name means "all such patches" (vs. only the threatened subset) — it is **not**
all greenery.

**Scope — what this is not:** it is 831 of the 1,142 `natural=forest` polygons in the raw
extract (5,007 ha of 16,291 ha). Excluded on purpose:
- **~311 polygons (~11,275 ha) outside Singapore** — the OSM extract bleeds into Johor,
  Malaysia (e.g. *Hutan Simpan Sungai Bahan*, *Hutan UTM*, *Pulau Merambong*); removed by
  clipping to the Singapore mask.
- **Other greenery tags** — `natural=park`, `landuse=grass/meadow/orchard/scrub`, etc. are
  not included. (`landuse=forest` and `natural=wood` don't exist in this extract, so nothing
  is lost there.)
- **The gazetted nature reserves** — Central Catchment (MacRitchie, Upper/Lower Peirce),
  Bukit Timah, and the Mandai forest are **absent from this OSM extract entirely**: probe
  points deep inside them hit no `natural` *or* `landuse` polygon. In OSM these are tagged
  `leisure=nature_reserve` / `boundary=protected_area`, which this Geofabrik-style extract
  (layers: natural, landuse, buildings, railways, points, waterways, places, roads) does
  not ship. So the largest contiguous green mass in Singapore is not in this layer.

Consequence: `forest_all` is **not** "all forest/greenery in Singapore" — it is the mapped
`natural=forest` patches, which skew toward *secondary-forest fragments outside the reserves*
(Toh Tuck, Clementi, Dover, etc.). This is fine for the headline question — the reserves are
protected, not development-zoned, so they are not part of the planned-deforestation footprint
— but it bounds what "forest" means here.

| Property | Meaning |
| --- | --- |
| `id` | OSM object id (matches `threatened_forests.id` for threatened patches) |
| `name` | OSM forest name, or `null` |
| `forest_area_ha` | Polygon area in hectares |
| `source_layer` | `natural` |
| `source` | `"OSM"` |

## 3. `development_zones.geojson` — context: the URA side
**Source:** `URA_MP2025` · **Geometry:** Polygon/MultiPolygon · **1,310 features**

The MP2025 development polygons that **overlap forest** (full, unclipped geometry — not
trimmed to the forest). This is the masterplan side of the overlay, so the app can show
the actual zoning parcels driving each flag. Only development-zoned parcels that touch
forest are included, not the whole 113k-feature masterplan.

| Property | Meaning |
| --- | --- |
| `id` | MP2025 `OBJECTID` |
| `lu_desc` | Land-use designation (e.g. `RESIDENTIAL`, `RESERVE SITE`, `ROAD`) |
| `gpr` | Gross plot ratio (numeric) or URA planning code |
| `area_ha` | Parcel area in hectares |
| `source` | `"URA_MP2025"` |

## 4. `summary.json` — totals, rankings, methodology
Not geometry — the numbers and narrative for the story. Top-level keys:

| Key | Contents |
| --- | --- |
| `generated_at` | UTC timestamp of the run |
| `provenance` | Input datasets and CRS used |
| `totals` | `total_forest_ha_sg`, `total_threatened_ha`, `threatened_fraction_of_mapped_forest`, polygon/patch counts |
| `by_lu_desc` | Threatened hectares broken down by land-use class (so no single number hides the mix) |
| `named_forests_threatened` | Named forests with their threatened hectares |
| `top_sites` | Ranked top 40 patches (same fields as layer 1, `centroid` as `[lon, lat]`) |
| `methodology` | Plain-language summary + the exact `development_zones` / `protected_zones_excluded` lists + scope note |
| `validation` | Embedded copy of the validation result |
| `caveats` | Interpretation limits (see below) |
| `layers` | Manifest of the three GeoJSON files (file → source, role, feature count) |

## 5. `validation.json` — is the method trustworthy?
Confirms the analysis independently recovers the two publicly-announced sites before we
trust anything new. `overall_pass` must be `true`.

| Field | Meaning |
| --- | --- |
| `overall_pass` | `true` if every site recovered |
| `sites[]` | Per-site: `site`, `method` (name match vs AOI), `forest_present_ha`, `threatened_ha`, `recovered` |

Maju Forest recovers by name (~21.7 ha); Gillman Barracks by location/AOI (~0.8 ha,
its surrounding forest is unmapped by name).

---

## Reading the numbers responsibly
- `area_ha` on layer 1 is the **overlap**, i.e. the at-risk portion — not the whole
  forest (that's `forest_area_ha`).
- A high `threatened_fraction` means the patch is almost entirely on development land.
- `RESERVE SITE` dominates the totals: that is land **reserved for future use** — a
  strong but *not imminent* development signal. `SPECIAL USE` may include land that
  stays forested. Always read `by_lu_desc` alongside the headline.
- This is the **planned footprint under MP2025**, not a measured increase vs MP2019.
